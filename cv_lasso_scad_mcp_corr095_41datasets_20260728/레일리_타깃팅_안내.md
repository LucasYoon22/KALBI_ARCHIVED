# 레일리 몫 타깃팅으로 합성 데이터 커버리지 넓히기

**한 줄**: 설계행렬을 그대로 두고 계수 벡터만 고유기저에서 배분하면, 레일리 몫
$R(\beta) = \mathrm{Var}(X\beta)/\|\beta\|^2$ 을 원하는 값에 **정확히** 맞출 수 있다.
근사가 아니라 등식이다. V14 생성기에 이걸 넣어 V15 를 만들었고, 508 샤드 전수로 검증했다.

작성 2026-08-15 · 대상 `generate_tabiclv2_..._mixedlinear_rayleigh_v15.py`

---

## 1. 왜 필요했나

KALBI 가 합성 데이터에서는 solution path 를 복원하는데 real 벤치마크 13개에서
무너졌다. 원인을 좁혀 가다가 나온 게 레일리 몫이다.

| | $R(\beta)$ 범위 |
|---|---|
| real 13 | $0.11 \sim 6.06$ |
| V14 생성 | 전부 $\approx 1$ |

100배 퍼진 영역을 한 점으로만 학습시키고 있었다. 그리고 이건 우연이 아니라
**구조적으로 그럴 수밖에 없었다.**

### 왜 V14 는 $R \approx 1$ 밖에 못 만드나

support $S$ 의 부분 그람 $G_S = X_S^\top X_S / n$ 을 두면, 열이 표준화돼 있으므로
$\mathrm{tr}(G_S) = k$ 이고 고유값은 전부 0 이상이다. 따라서

$$R(\beta) \le w_{\max} \le \mathrm{tr}(G_S) = k$$

V14 의 support 크기 중앙값이 **4** 였다. $R$ 이 4 를 넘을 방법이 없다.
상한이 `max_support = min(p, (n-1)//3)` 이었는데, 실제로 뽑히는 $k$ 는 그보다
훨씬 작았다.

그리고 무작위 support 로는 $w_{\max}$ 가 2~3 에서 포화된다. 서로 무관한 열
$k$ 개를 모아봐야 그람이 단위행렬에 가깝고, 그러면 $R \approx 1$ 이다.

## 2. 메커니즘

### 핵심 항등식

$G_S = V \operatorname{diag}(w) V^\top$ 로 고유분해하고 $\beta_S = Vc$ 로 두면

$$R(\beta) = \frac{\beta_S^\top G_S \beta_S}{\beta_S^\top \beta_S}
           = \frac{\sum_i c_i^2 w_i}{\sum_i c_i^2}$$

즉 **$R$ 은 고유값의 가중평균**이고, 가중치는 우리가 정하는 $c_i^2$ 다.

### 정확히 맞추기

목표 $R^\star$ 를 감싸는 인접 고유값 쌍 $w_a \le R^\star \le w_b$ 를 찾아

$$c_a^2 = \frac{w_b - R^\star}{w_b - w_a}, \qquad
  c_b^2 = \frac{R^\star - w_a}{w_b - w_a}$$

로 두고 나머지는 0. 그러면 $c_a^2 + c_b^2 = 1$ 이므로

$$R(\beta) = c_a^2 w_a + c_b^2 w_b
= \frac{(w_b - R^\star) w_a + (R^\star - w_a) w_b}{w_b - w_a} = R^\star$$

**분자를 전개하면 $w_a w_b$ 항이 소거되고 $R^\star(w_b - w_a)$ 만 남는다.**
반복도, 최적화도, 튜닝도 없다. 한 번에 정확히 맞는다.

### 퇴화 방지

위 구성은 고유기저에서 rank-2 다. 그대로 두면 β 가 항상 2차원 부분공간에
갇히므로, **등방 성분 15%** 를 섞는다. 섞은 뒤 $R$ 을 다시 계산해 기록하므로
메타데이터의 `linear_rayleigh_quotient` 는 언제나 실측값이다.

### 상관 블록 support

고유값 스프레드가 없으면 타깃팅할 여지도 없다. 무작위 support 는 스프레드가
좁아서, 씨앗 열 하나를 잡고 **절대상관 상위 $k-1$ 개**를 붙이는 모드를 추가했다.
세 모드를 확률 $1/3$ 씩 쓴다.

| 모드 | 동작 |
|---|---|
| `random` | 기존과 동일 |
| `correlated_block` | 씨앗 1개 + 상관 상위 $k-1$ 개 |
| `mixed` | 절반 블록, 절반 무작위 |

큰 $p$ 에서 $n \times p$ 복사를 피하려고 `einsum` 으로 처리한다.

```python
cross = x64.T @ (x64[:, seed] - mean[seed])
norm_squared = np.einsum("ij,ij->j", x64, x64) - n * mean * mean
correlation = np.abs(cross) / np.sqrt(norm_squared * norm_squared[seed])
```

### support 상한 완화

```diff
- max_support = min(p, (n - 1) // 3)
+ max_support = min(p, int(0.60 * (n - 1)))
```

`3k < n` 을 강제에서 **기록으로** 바꿨다 (`linear_support_strict_n_third_verified`).
아래 결과에서 보듯 이 완화 자체는 거의 안 쓰였다.

## 3. 검증 결과

### 커버리지

| | V14 | V15 |
|---|---|---|
| $R(\beta)$ 범위 | 전부 $\approx 1$ | $0.106 \sim 8.47$ |
| $R < 1$ 비율 | $\approx 0\%$ | 45% |
| $R > 3$ 비율 | 0% | 13% |
| $\max \|\beta\|$ | 1.144 | 3.08 |

real 의 $[0.11,\ 6.06]$ 이 완전히 안에 들어온다. 140개 태스크로 독립 측정했을 때
실현 $R$ 의 최소가 0.1056, 9% 가 0.4 미만이었다.

### 생성 실적

508 샤드 생성, 학습 카탈로그에 **481개 등록, 27개(5.3%) 제외**.
제외 사유는 트레이너의 태스크당 $3k < n$ 인증을 못 넘은 것 — 그 검증을
**약화시키지 않고** 그대로 둔 채 걸러냈다.

**이 5.3% 이 그 자체로 결과다.** 스무 개 중 하나만 $n/3$ 보다 큰 support 를
필요로 했다는 뜻이고, 곧 **커버리지를 번 건 상한 완화가 아니라 고윳값 타깃팅**
이라는 증거다. §2 의 상한 완화는 곁가지였다.

### 온전성 검사

생성기가 항상 `beta /= np.std(signal)` 로 $\mathrm{Var}(X\beta) = 1$ 을 맞추므로

$$R(\beta_{\mathrm{true}}) = \frac{1}{\|\beta_{\mathrm{true}}\|^2}$$

이 정확히 성립한다. 메타데이터의 `linear_rayleigh_quotient` 와
$1/\|\beta\|^2$ 를 대조하면 파이프라인 어디가 깨졌는지 바로 잡힌다.

### 상관 구조 (0.95 필터 통과 후)

| | real (13) | V15 (508) |
|---|---|---|
| median $\|\mathrm{corr}\|$ | 0.0278 | 0.0230 |
| 정확 max, 중앙 | 0.9248 | 0.8498 |
| 정확 max, 최대 | 0.949938 | 0.938114 |
| 0.95 초과 | 0 | **0 / 508** |

필터를 정확히 지켰고 전형적인 쌍의 상관도 real 과 사실상 같다.

## 4. 이게 **안** 고치는 것

여기가 중요하다. 레일리 타깃팅은 **계수 쪽** 개입이라 설계행렬은 안 건드린다.
따라서 다음 둘은 그대로 남는다.

### 상관된 설계의 빈도

패널당 상위 1% 상관을 $q_{99}$ 로 재면 (508 전수):

| $q_{99}$ | real (13) | V15 (508) |
|---|---|---|
| 최소 | 0.219 | 0.052 |
| **중앙** | **0.416** | **0.154** |
| 최대 | 0.913 | 0.584 |

V15 의 최대 0.584 가 real 13개 중 11개보다 높다. 즉 **못 만드는 게 아니라
드물게 만든다.** real 중앙값에 도달하는 샤드가 14개(2.8%) 뿐이다.

고치려면 `SUPPORT_SELECTION_PROBABILITIES` 를 `correlated_block` 쪽으로
기울이면 된다. 새 메커니즘이 아니라 숫자 하나다.

### 문제 크기

shape 샘플러는 V14 에서 그대로 물려받았다 (`exp122_shape_sampler`).

| | V15 (508) | real (13) |
|---|---|---|
| $n$ 중앙 | 1,999 | 497 |
| $p$ 중앙 | **10,285** | **988** |
| $n \times p$ 중앙 | 24.0M | 0.5M |

508개 중 **375개(74%)가 `max_cells` 상한 24M 에 붙어 있다.** 샘플러가 셀 예산을
계통적으로 다 쓰고, $n$ 이 real 과 비슷하니 그 예산이 전부 $p$ 로 간다.
결과적으로 real 의 $(n, p)$ 범위 안에 드는 V15 샤드가 **16개(3.1%)** 뿐이다.

이건 관찰이지 진단이 아니다. 인과를 세운 적 없다. 다만 위의 $q_{99}$ 격차와
얽혀 있다 — $p$ 가 10배 넓으면 같은 양의 상관 구조가 희석되므로, $q_{99}$ 차이의
일부는 메커니즘이 아니라 $p$ 탓일 수 있다.

### 타깃팅을 건너뛰는 경우

- 동전 던지기 15% (`RAYLEIGH_TARGET_PROBABILITY = 0.85`)
- $k < 2$ — $G_{SS}$ 가 스칼라 1 이라 $R \equiv 1$, 타깃팅이 불가능
- $k > 768$ — 고유분해 비용
- 고유값 스프레드 $< 10^{-9}$, 또는 `eigh` 실패

건너뛰면 기존 등방 샘플러를 그대로 탄다. **그래서 V14 분포가 데이터에 상당 비율
남아 있고, 재학습 시 기존 성능이 통째로 사라질 위험이 낮다.**

### 새로 생기는 메타데이터

```

linear_rayleigh_targeted          타깃팅을 탔는가
linear_rayleigh_target            목표 R*
linear_rayleigh_realized_presignal  스케일 정규화 전 실현값
linear_subgram_eig_min/max/mean   부분 그람 고유값
linear_rayleigh_eig_index_low/high  쓴 인접 쌍의 인덱스
linear_rayleigh_isotropic_mix     혼합 비율
linear_support_selection(_id)     support 선택 모드
linear_support_seed_column        블록 씨앗 열
```

**학습 런치의 `--expected-pipeline-sha256` 을 새 해시로 바꿔야 한다.**
트레이너 쪽 상수 세 개도 같이 맞춰야 한다 (`apply_v15_contract_patch.py` 참고):

## 6. 언제 이걸 쓰면 되나 / 안 되나

**쓰면 좋은 경우**

- 생성기가 $R \approx 1$ 만 뱉어서 저-$R$ 영역 성능을 못 재는 상황
- 설계행렬 생성 파이프라인은 검증돼 있어서 건드리고 싶지 않은 경우
  (타깃팅은 계수만 만지므로 SCM/필터/표준화가 그대로 유지된다)
- $R$ 을 특정 값으로 **정확히** 고정한 통제 실험이 필요한 경우

**이걸로 안 되는 경우**

- 조건수 나쁜 설계, near-collinear 블록, 낮은 effective rank 가 필요한 경우
  → 설계 쪽 개입이 필요하다. 계수를 아무리 배분해도 $G_S$ 자체는 안 바뀐다.
- $(n, p)$ 분포를 맞춰야 하는 경우 → shape 샘플러 문제다 (§4)
- $k < 2$ 인 태스크가 많은 경우 → 수학적으로 $R \equiv 1$ 이라 손댈 수 없다

**주의**

평가셋에 맞춰 생성기를 조이는 건 과적합이다. real 13개에 $(n, p)$ 와 상관을
맞추면 점수는 오르겠지만, 그게 모델이 나아진 건지 커닝인지 구분이 안 된다.
생성기를 고치기 전에, **$p$ 를 벤치마크 범위로 제한한 held-out split** 으로
먼저 진단하는 편이 정직하다.
